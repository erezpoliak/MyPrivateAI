# Agentic RAG Workflow

## Overview

Critique-driven multi-hop RAG pipeline. The critique evaluates answer quality
against the original question — not retrieval quality — because answer correctness
is the metric that matters (measured by RAGAS).

## Flow

```
Hop 1: retrieve(original Q) --> synthesize(original Q) --> critique
  PASS --> done
  FAIL -->

Hop 2: decompose(critique) --> retrieve(sub-Q) --> synthesize(original Q) --> critique
  PASS --> done
  FAIL -->

Hop 3: decompose(critique) --> retrieve(sub-Q) --> synthesize(original Q) --> critique
  PASS --> done
  FAIL --> correct(critique) --> done
```

## Steps

### Retrieve (every hop)
Fetches document chunks from the hybrid retriever (vector + BM25 + reranking).
Hop 1 uses the original question as the retrieval query.
Hop 2+ uses a sub-question generated by decompose.

### Synthesize (every hop)
Answers the **original question** (not the sub-question) using **all** accumulated
chunks across all hops. Context grows with each hop. Uses `FINAL_SYNTHESIS_PROMPT`.

### Critique (every hop)
Evaluates the synthesized answer against the original question. Checks for:
1. Completeness — does it address every part of the question?
2. Faithfulness — is every claim supported by the context?
3. Accuracy — are there factual errors?

Outputs PASS (stop) or FAIL (with explanation of deficiencies).

### Decompose (hop 2+ only)
Generates a targeted retrieval query to fill the gap identified by critique.
Receives:
- The original question
- List of queries already tried (to avoid repetition)
- The latest critique text (to target specific gaps)

The sub-question is **only a retrieval query** — it is never answered separately.

### Correct (last resort)
Runs only when all hops are exhausted and critique still says FAIL.
Rewrites the answer using the critique's specific deficiencies as guidance.
Same accumulated context — no new retrieval.
